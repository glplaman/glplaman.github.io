用户界面设计

UI
用户界面设计是接口设计的一个组成部分
在系统软件设计中所占的比例越来越大，个别情况甚至占到了总量的一半
用户界面设计质量直接影响用户对软件产品的评价，从而影响软件产品的竞争力和寿命
存在的问题 Focus
  1. 系统响应时间

    从用户完成某个控制动作（按回车键或单击鼠标）到软件给出预期的响应（输出或做动作）之间的时间

    响应时间有两个属性：长度和易变性

    响应时间过长，用户会不满意；响应时间过短，会迫使用户加快操作节奏，从而可能会犯错误

    即响应时间相对于平均响应时间的偏差。响应时间易变性低，有助于用户建立稳定的工作节奏；响应时间的变化暗示系统工作出现了异常

  2. 用户帮助设施

    集成的帮助设施设计在软件里，对用户工作内容敏感，用户可从与操作有关的主题中选择一个，请求帮助。它可以缩短用户获得帮助的时间，增加界面的友好性

    附加的帮助设施实际是一种查询能力有限的联机用户手册

    集成的帮助设施优于附加的帮助设施

  3. 出错信息处理

    定义：出错信息和警告信息是出现问题时给出的坏消息。有效的出错信息能提高交互系统的质量，减少用户的挫折感

    信息应以用户可理解的术语描述问题

    信息应提供有助于从错误中恢复的建设性意见

    信息应指出错误可能导致的负面后果（例如，破坏数据文件），以便用户检查是否出现了这些问题，并在问题出现时予以改正

    信息应伴随听觉上或视觉上的提示，在显示信息时同时发出警告声或用闪烁方式显示，或用明显的颜色表示出错信息

    信息不能指责用户

  4. 命令交互

    每个菜单项都应有对应的命令

    命令形式：控制序列（例如，Ctrl＋P）、功能键、键入命令

    学习和记忆命令的难度，忘记了命令怎么办

    用户是否可以定制或缩写命令

    命令宏：代表一个常用的命令序列。只需输入命令宏的名字就可以顺序执行它所代表的全部命令

    所有应用软件都应有一致的命令使用方法

    5. 面向窗口、单击和拾取方式的界面已减少了用户对命令行的依赖，但是还是有些用户偏爱命令方式进行交互

设计过程 Process
  1. 先创建设计模型，实现模型——用户界面原型
  2. 用户试用并评估该原型，向设计者提出对界面的评价
  3. 设计者根据用户的意见修改设计并实现下一级原型
  4. 不断进行下去，直到用户感到满意为止
设计标准 Standards
  1. 系统及其界面的规格说明的长度和复杂程度，预示了用户学习使用该系统所需的工作量
  2. 命令或动作的数量、命令的平均参数个数或动作中单个操作的个数，预示了系统的交互时间和总体效率
  3. 动作、命令和系统状态的数量，预示了用户学习使用系统时需要记忆的内容的多少
  4. 界面风格、帮助设施和出错处理协议，预示了界面的复杂程度和用户对该界面的接受程度
设计指南 Guidelines
  1. 一般交互

    保持一致性：菜单选择、命令输入、数据显示、其他功能要使用一致的格式

    提供有意义的反馈：提供视觉、听觉的反馈，建立双向通信

    要求确认：在执行有破坏性动作之前要求用户确认“是否确实要……”

    允许取消操作：能方便地取消已完成的操作

    尽量减少记忆量

    提高效率：对话、移动、思考等要提高效率。允许用户犯错误：系统应保护自己不受致命错误的破坏

    按功能对动作分类：如下拉菜单。应尽力提高命令和动作的内聚性

    提供帮助设施

    命令名要简单：用简单动词或动词短语作为命令名

  2. 信息显示

    用户界面显示的信息应完整、清晰、易于理解

    可用不同方式显示信息：例如：文字、图片、声音、位置、移动、大小、颜色、分辨率和省略

    只显示与当前工作内容有关的信息

    使用一致的标记、标准的缩写、可预知的颜色，显示的含义应非常明确

    允许用户保持可视化语境。若对图形进行放缩，原始图形应一直显示

    产生有意义的出错信息

    使用大小写、缩进和文本分组帮助理解

    使用窗口分隔不同类型的信息

    使用模拟显示方式表示信息。例如，用颜色变化表示警告信息等

    高效率地使用显示屏。使用多窗口时，应使每个窗口都有空间显示信息。屏幕大小应选择得当

  3. 数据输入

    尽量减少用户的输入动作。用鼠标从预定的一组输入中选择一个；然后在给定的值域中指定输入值；利用宏命令把一次击键转变为复杂的输入数据集

    保持信息显示和数据输入的一致性，如文字大小、颜色、位置与输入一致

    允许用户自己定义输入，如定义专用命令、警告信息和动作确认等

    允许用户选择输入方式（键盘、鼠标）等

    使当前不适用的命令不起作用

    让用户控制交互流程。跳过不必要的动作，改变工作的顺序，从错误状态中恢复正常

    对所有的输入动作提供帮助

    消除冗余的输入。绝对不要要求用户提供程序可以自动获得或计算出来的信息。例如，当前日期、时间等可以自动获得；又如姓名、性别、部门、职称等信息预先存放在数据库里，只要输入职工号，就可以程序调用显示其对应的姓名、性别、部门、职称等信息；整数后面不要求用户输入“00”
