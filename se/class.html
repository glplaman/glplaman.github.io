类与类之间的六种核心关系，从强到弱分别是：
泛化 Generalization
类的继承关系
类A继承了类B
使用关键字 extends 继承一个类
public class Person{
    private String name;
    private Integer age;
    private String address;
}

public class Student extends Person{
}

public class Teacher extends Person{
}
实现 Realization
类和接口的关系
类A实现了接口B
一个类可以实现多个接口
使用关键字 implements 声明一个接口
public interface USB{
    void connect();
}

public class Mouse implements USB{
    private void connect(){
    }
}

public class Keyboard implements USB{
    private void connect(){
    }
}
组合 Composition
整体和部分的关系
类A包含类B
一旦整体不存在，部分也就不存在|部分不能脱离整体而单独存在
生命周期有制约关系
部分随着整体创建而创建，随着整体消亡而消亡
public class Product{
    private String name;
    private Integer sn;
}

public class OrderItem{
    private Integer nums;
    private double price;
    private Product product;
}

public class Order{
    private List<OrderItem> item;
}
聚合 Aggregation
整体和部分的关系
类A聚合了类B；一个类作为另外一个类的成员对象|属性；包含多个成员对象；将多个部分聚合到一起
但是部分可以脱离整体而独立存在
public class University{
    private List<Teacher> teacher;
}

public class Teacher{
    private String name;
    private String dep;
}
public class Car{
    private Engine engine;
    private List<tyre> tyres;
}

public class Engine{
    private String fac;
    private Integer sn;
}

public class Tyre{
    private String fac;
    private Integer sn;
    private String color;
}
购物车与商品
购物车作为“整体”，包含（拥有）多个商品作为其“部分”
商品的生命周期是独立的。一个商品可以从购物车中移除，它本身依然存在；一个空的购物车也可以被创建。因此，商品并不依赖于购物车而存在。

类的使用关系
类A使用了类B或作为局部变量，或作为方法的参数；即：类B作为类A的方法的参数或局部变量存在
这个使用是临时的、偶然的、弱关系
尽量不要使用双向依赖，耦性太强
某电商系统在采用面向对象方法进行设计时，识别出网店、商品、购物车、订单买家、库存、支付(微信、支付宝)等类。其中，购物车与商品之间适合采用( )关系，网店与商品之间适合采用( )关系。
