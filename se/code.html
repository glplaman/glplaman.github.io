代码设计

Code
代码是为了对数据进行识别、分类、排序等操作所使用的数字、文字或符号
必须从系统的整体出发，综合考虑各方面的因素，精心设计信息代码
在一个系统中，如果使用的代码复杂、量大，人们无法准确地记忆，可以用 代码词典 记录代码与数据之间的对应关系
必要时，可以设计代码 联机查询 功能，以方便用户的使用和查找
有时，代码需要随时进行增加、删除、修改、查询等，可以设计相应的代码管理功能
为了追踪和溯源，使用仓库化关联已成常态；如 GIt / Github

特点 Features
  1. 简洁性：代码可以减少存储空间，要求消除二义性
  2. 保密性：不了解编码规则的人不知道代码的含义
  3. 可扩充性：设计代码时要留有余地，方便软件生存期内增加代码
  4. 持久性：代码应可以在软件生存期内长久使用。设计代码时，要考虑到代码的变换会影响数据库和程序
设计原则 Rules
  1. 标准化

    核心要求：尽可能采用国际标准、国家标准、部颁标准、行业标准或遵循惯例

    目的：以便信息的交换和维护

  2. 唯一性

    核心要求：一个代码只代表一个信息，每个信息只有一个代码

    目的：确保数据的一致性和准确性，避免歧义

  3. 可扩充性

    核心要求：设计代码时要留有余地

    目的：方便代码的更新、扩充，以适应未来的变化

  4. 简单性

    核心要求：代码结构简单、尽量短

    目的：便于记忆和使用，降低使用成本

  5. 规范化

    核心要求：代码的结构、类型、缩写格式要统一

    目的：保持系统内部的整齐划一，便于管理

  6. 适应性

    核心要求：代码要尽可能反映信息的特点，唯一地标识某些特征（如物体的形状、大小、颜色，材料的型号、规格、透明度等）

    目的：使代码具有实际意义，便于识别和理解

设计方法 Approach
  1. 确定编码对象

    选择那些采用代码后能显著提高输入、输出和查询效率的数据作为编码对象

    例如学校的学生、教师、图书、设备，或商场的商品、供货单位、财务科目等

  2. 一个数据存储不一定是一个文件

    确定编码后，需要评估其在识别、分类、排序等方面的重要性

    不同的编码目的，所选用的代码种类也会不同

  3. 数据存储和数据流都是数据

    确定当前的代码数目以及未来可能需要扩充的代码数目，为设计预留空间

  4. 确定代码的使用范围和使用期限

    明确代码可以在哪些范围内使用，以及它的有效期限是多久

  5. 确定代码体系和代码位数

    这是编码的关键步骤

    设计的代码应简短、易记、不易混淆。需要根据代码的使用目的来决定采用哪种编码体系和具体的位数

  6. 确定编码规则

    编码规则的制定需要与最终使用人员密切合作、认真讨论

    综合考虑使用需求、计算机处理的便捷性、以及代码的易记性和可维护性

  7. 编写代码

    在明确了编码目的、对象，并确定了编码规则、代码个数、使用范围、期限、体系和位数等一系列问题后，就可以正式开始编写代码了

  8. 编写代码词典
    9. 数据量小：在数据字典中将代码与数据的对应关系一一列出。 数据量大：应当编写专门的代码词典。词典中应记录数据与代码的对应关系、使用方法与示例、修改代码的手续及规则、以及代码管理的部门和权限等。
