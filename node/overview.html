概述

Overview
统一资源定位 URL
资源：指在互联网上可以被访问的任何对象，包括文件目录、文件、文档、图像、声音等，以及与互联网相连的任何形式的数据
互联网上的资源，都有一个唯一确定的 URL
对字符大写或小写没有要求
URL
item desc
schema 协议；HTTP、HTTPS、FTP
host 主机名；以域名或IP地址表示，如glpla.github.io或185.199.109.153
port 端口；HTTP 默认 80
path 路径；请求资源在服务器上的具体位置；默认为 /，根路由
query 查询参数；以 ? 拼接值对键值对参数，多个值对使用 & 连接
fragment 锚点；锚链接，以 # 表示，用以定位页面某个位置；也叫哈希值 Hash
[] URL示例
类型
指的是HTTP的请求方式
早期多依托表单 <form>；现在多使用自定义事件，可以抛弃 <form> 这个壳
请求类型
item desc
GET 获取资源
POST 提交资源
PUT 修改资源
DELETE 删除资源
1. GET
参数通过 URL 查询字符串传递（如 ?id=123&name=张三）
不能携带复杂数据（受限于 URL 长度）
可被缓存、可收藏、可书签
必须是只读操作（不应修改数据）
2. POST
数据放在请求体中（body），支持任意格式（JSON、form-data 等）
不是幂等的（多次提交可能创建多个资源）
通常用于新建记录、登录、评论等
提交的数据包含请求类型 Content-Type 和消息主体编码方式两部分
常见 Content-Type
item desc
application/x-www-form-urlencoded HTML 表单提交时浏览器默认的编码方式
使用键值对参数
适用于普通文本数据，不支持文件上传
multipart/form-data 用于上传文件或包含二进制数据的表单
必须指定 <form> 的 enctype 为该值
application/json 发送 JSON 数据的标准格式
常用于 API 接口通信，如 RESTful 接口
text/plain 纯文本内容，无任何结构或编码规则
可用于发送简单字符串、日志、配置等
text/xml 用于发送 XML 文档
已逐渐被 JSON 取代
Restful API
Representational State Transfer
由 Roy Fielding 在 2000 年博士论文中提出的一种软件架构风格，不是协议、不是标准，而是一组设计约束
HTTP 请求方法是实现 RESTful API 的核心工具
