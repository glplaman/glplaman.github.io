[ 理论讲解 Lecture on Theory ]

1. 概述 Overview

  • 创建型 Creational 设计模式
  • 一个类仅有一个实例 - single instance

    控制类的实例化过程，确保一个类在整个程序运行期间只存在一个实例

    避免全局使用的类-频繁-的创建和销毁，占用和消耗系统资源

  • 提供一个全局访问点

    通过静态方法或属性，如 getInstance()，让所有模块都能访问这个唯一的实例

    避免了直接使用全局变量带来的混乱和耦合问题

2. 特性 Feature

  • 唯一实例
  • 全局访问
  • 延迟初始化

    实例不是一开始就创建，而是在第一次被请求时才创建

    加快首屏启动时间

    节省系统资源

4. 实现 Implementation

4.0. 基本思路

  • 实例化的时候，判断是否已经拥有一个实例

    有，返回已经创建的实例

    没有，创建实例

4.1. 基本方案 - 使用函数

  • 闭包 Closure

    延长了变量的生命周期

    实现数据私有化（类似私有变量），外部无法直接访问

    可能导致内存泄漏（如果闭包引用了大对象且未释放）

    声明

    const outer = () => {
    let age = 18;
    return inner = () =>{
        return age;
    };
}

    执行，拿到函数 inner()

    outer()

    再执行，访问到 age

    outer()()

    inner 函数形成了一个闭包，它-记住-了 outer 中的 age 变量

    即使 outer() 已经执行完毕，age 依然存在，并被 inner 所引用

  • 立即执行函数 IIFE - Immediately Invoked Function Expression

    定义后立即被调用 - 简化操作

    通常用于创建私有/独立作用域，使得其中的变量 instance 成为真正的私有静态变量

    避免污染全局命名空间

    ;(() => {
  // 函数体
})();
  • 单例实现

    借助闭包和立即执行函数实现

    • const Singleton = (() => {
  let instance;
  
  return () => {
    if (!instance) {
      // ...
    }
    return instance;
  };
})();
    [] 使用时间戳为例，创建单例并验证
  • 创建
    • const singletonTime = (() => {
  let timer;
  return () => {
    if (!timer) {
      timer = new Date().getTime()
    }
    return timer
  }
})()
  • 使用定时器验证
    • let t0 = singletonTime()
console.log(t0);

setTimeout(() => {
  let t1 = singletonTime()
  console.log(t1);
  console.log(t0 == t1);
  console.log(t0 === t1);
}, 3000)
  • 特点

    JavaScript 支持较好；低版本也可以正常使用

    语法略显复杂，可读性不如类

    返回的是函数，调用时是 Singleton()，不像构造函数 new Singleton() 直观

    如果初始化逻辑复杂，代码组织不如类清晰

    • 单例创建后，也可以直接使用开发者工具验证，并思考为什么t1会提示未定义？

    在获取时间戳的逻辑中，定义自己需要的任何逻辑即可

4.2. 进阶方案 - 使用类

  • 类 Class

    在 constructor 中检查 Singleton.instance 是否存在

    若存在，直接返回已有实例，跳过初始化

    否则创建新实例并赋值给 Singleton.instance

    定义

    class Singleton {
  constructor() {
    if (!Singleton.instance) {
      // ...
      Singleton.instance = this;
    }
    
    return Singleton.instance;
  }
  
  // methods
  // ...
}

    验证

    const instance1 = new Singleton();
const instance2 = new Singleton();
console.log(instance1 === instance2); // true
  • 特点

    语法清晰，符合现代编码规范

    调用方式自然：new Singleton()

    易于扩展，支持继承

    Singleton.instance 是暴露的，可能被外部修改或重置。如何避免？

4.3. 终极方案 - 使用模块

  • 模块 Module

    利用 ES Module 的特性：模块是单例的，import 多次也只加载一次

    直接导出一个实例，而不是类

    天然单例：JS 模块系统保证了这一点

  • 特点

    最简单、最安全：没有手动检查实例的逻辑

    易于测试；可通过 mock 模块替换

    无法延迟初始化 lazy initialization：模块加载时就创建实例，即使还没用到

    如果初始化依赖运行时参数，如配置，会受限

    不适合需要"按需创建"的场景

    • // singleton.js
class Singleton {
  constructor() {
    this.data = [];
  }
  
  getData() {
    return this.data;
  }
  
  addData(item) {
    this.data.push(item);
  }
}

// 导出单例实例
export default new Singleton();
