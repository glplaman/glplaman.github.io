邮件接收协议

POP3（Post Office Protocol version 3）和 IMAP（Internet Message Access Protocol）是两种用于从邮件服务器下载或访问电子邮件的协议
都是基于 TCP 使用客户/服务器 C/S 方式
下图使用POP3协议
邮局协议 POP3
Post Office Protocol version 3
3 表示第3个版本
端口 110：标准 POP3 端口（明文或 STARTTLS）
端口 995：POP3S（POP3 over SSL/TLS），加密连接
用户连接服务器 → 一次性下载所有新邮件 → 默认从服务器删除
基本流程

客户端连接 POP3 服务器（端口 110）

认证（用户名/密码）

列出邮件列表（LIST 命令）

下载邮件（RETR 命令）

标记为删除（DELE），退出时真正删除（QUIT）

特点

无法多设备同步：在手机上读了邮件，电脑上看不到“已读”状态

容易丢失邮件：如果本地设备损坏且服务器已删邮件，数据无法恢复

功能单一：不能远程管理文件夹、搜索服务器内容等

IMAP
Internet Message Access Protocol
IMAP（明文或 STARTTLS）：端口 143
IMAPS（SSL/TLS 加密）：端口 993
邮件始终保存在服务器上
客户端通过 IMAP 同步访问服务器上的邮件，所有操作都在服务器上完成，支持多设备实时同步
所有操作（读、删、移、标星）实时同步到所有设备
基本流程

客户端连接 IMAP 服务器（端口 143 或 993）

身份验证（用户名/密码）

获取邮箱列表（如收件箱、发件箱、草稿等）

同步邮件状态（未读/已读、星标、移动等）

实时操作（读、删、移、搜索、过滤）都会反映在服务器上

支持文件夹层级管理和邮件分类

特点

要想查阅邮件，必须先联网

占用服务器存储空间

对服务器性能要求高

POP3：适合只想下载邮件并离线阅读的用户，但缺乏同步能力

IMAP：适合需要多设备同步、远程管理、实时更新的现代用户，是当前主流选择

MIME

Multipurpose Internet Mail Extensions
用于扩展电子邮件；支持

非 ASCII 字符（如中文、阿拉伯文等）

附件（如图片、音频、视频、PDF 等二进制文件）

多部分消息体（例如：一封邮件同时包含纯文本和 HTML 版本）

邮件内容的编码方式
不是传输协议，因此不绑定端口号
MIME 的三大主要功能
1. 定义了 5 个新的邮件首部字段（Header Fields）
这些字段嵌入在邮件头部，用于描述邮件内容的结构和编码方式：

MIME-Version：表明该邮件符合 MIME 标准（通常为 1.0）

Content-Type：指定主体（body）的数据类型（如 text/plain、image/jpeg、multipart/mixed）

Content-Transfer-Encoding：说明主体如何被编码以通过邮件系统安全传输（如 base64、quoted-printable）

Content-ID：为内容部分分配唯一标识符（常用于 HTML 邮件中引用内嵌图片）

Content-Description：对内容进行可读性描述（可选）

Content-Type 说明必须含有两个标识符
内容类型 (type) 和子类型 (subtype)，中间用“/”分开
MIME 标准原先定义了 7 个基本内容类型和 15 种子类型
MIME 允许发件人和收件人自己定义专用的内容类型。但为避免可能出现名字冲突，标准要求为专用内容类型选择的名字要以字符串 X-开始
Content-Type
item desc
text 文本类；子类型有 /plain /html /css /xml /csv；通常需要指定编码，如 charset=utf-8
image 图像类；子类型有 /jpeg /png /gif /webp /svg+
application 应用类；子类型有 /json /javascript /xml /msword /octet-stream
multipart 混合类；子类型有 /form-data
audio 音频类
video 视频类
2. 定义了许多邮件内容的格式，对多媒体电子邮件的表示方法进行了标准化
支持非 ASCII 文本（如中文、日文、阿拉伯语等）
支持多种媒体类型：文本、图像、音频、视频、应用程序文件等
引入 多部分（multipart） 结构，使一封邮件可包含多个独立部分（例如：正文 + 附件，或纯文本 + HTML 版本）
常见类型：

multipart/mixed：混合内容（正文+附件）

multipart/alternative：同一内容的不同格式（如 text 和 HTML）

multipart/related：主文档与关联资源（如 HTML + 内嵌图片）

3. 定义了传送编码（Transfer Encodings），可对任何内容格式进行转换，而不会被邮件系统改变
传统 SMTP 只支持 7-bit ASCII，无法直接传输二进制数据
MIME 引入两种安全编码方式：

Base64：将任意二进制数据转换为 ASCII 字符，适合图片、PDF 等

Quoted-Printable：仅对非 ASCII 或特殊字符编码，适合含少量非英文字符的文本

接收方根据 Content-Transfer-Encoding 字段自动解码，还原原始内容
Transfer Encodings
item desc
7bit 7 位 ASCII 编码，每行不能超过 1000 个字符（包括回车和换行）
默认编码方法
8bit 8 位非 ASCII 编码，每行不能超过 1000 个字节（包括回车和换行）
Binary 8 位非 ASCII 编码，任意长度的字节串
Base64 将任意长度的字节串转换为用 7 位 ASCII 编码表示的字符串
可用于二进制和非文本数据的编码
Quoted-printable 将任意长度的字节串转换为 ASCII 编码表示的字符串
可用于二进制和非文本数据的编码
