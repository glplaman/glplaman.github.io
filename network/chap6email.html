简单邮件传送协议 SMTP

Simple Mail Transfer Protocol - SMTP
基于 TCP
使用 ASCII 码

不支持非英文字符，如中文

采用客户/服务器 C/S 模式

涉及两个 C/S 交互
发送方邮件代理 → 发送方邮件服务器（SMTP Client → SMTP Server）

邮件发送

发送方邮件服务器 → 接收方邮件服务器（SMTP Client → SMTP Server）

接收方邮件服务器使用端口 25

连接建立

发送主机的 SMTP 客户和接收主机的 SMTP 服务器之间建立

不使用中间的邮件服务器 - 教学简化模型或理想化场景

但是仍然需要中间的站点即邮件传输代理 MTA（Mail Transfer Agent）转发

SMTP 客户首先使用熟知端口 25 与接收方的 SMTP 服务器建立 TCP 连接
SMTP 服务器发出服务就绪
SMTP 客户向服务器发送问候 HELO 命令，附上发送方的主机名

1. 信封阶段（Envelope Phase）

2. 内容阶段（Data Phase）

内容以 <CRLF>.<CRLF> 结束（即空行后跟一个点）

邮件接收协议

POP3（Post Office Protocol version 3）和 IMAP（Internet Message Access Protocol）是两种用于从邮件服务器下载或访问电子邮件的协议
都是基于 TCP 使用客户/服务器 C/S 方式
下图使用POP3协议
邮局协议 POP3
Post Office Protocol version 3
3 表示第3个版本
端口 110：标准 POP3 端口（明文或 STARTTLS）
端口 995：POP3S（POP3 over SSL/TLS），加密连接
用户连接服务器 → 一次性下载所有新邮件 → 默认从服务器删除
基本流程

客户端连接 POP3 服务器（端口 110）

认证（用户名/密码）

列出邮件列表（LIST 命令）

下载邮件（RETR 命令）

标记为删除（DELE），退出时真正删除（QUIT）

特点

无法多设备同步：在手机上读了邮件，电脑上看不到“已读”状态

容易丢失邮件：如果本地设备损坏且服务器已删邮件，数据无法恢复

功能单一：不能远程管理文件夹、搜索服务器内容等

IMAP
Internet Message Access Protocol
IMAP（明文或 STARTTLS）：端口 143
IMAPS（SSL/TLS 加密）：端口 993
邮件始终保存在服务器上
客户端通过 IMAP 同步访问服务器上的邮件，所有操作都在服务器上完成，支持多设备实时同步
所有操作（读、删、移、标星）实时同步到所有设备
基本流程

客户端连接 IMAP 服务器（端口 143 或 993）

身份验证（用户名/密码）

获取邮箱列表（如收件箱、发件箱、草稿等）

同步邮件状态（未读/已读、星标、移动等）

实时操作（读、删、移、搜索、过滤）都会反映在服务器上

支持文件夹层级管理和邮件分类

特点

要想查阅邮件，必须先联网

占用服务器存储空间

对服务器性能要求高

POP3：适合只想下载邮件并离线阅读的用户，但缺乏同步能力

IMAP：适合需要多设备同步、远程管理、实时更新的现代用户，是当前主流选择
