签名过程 Signature
  1. Alice 采用摘要算法如 MD5 对原始消息计算得到摘要
  2. 使用自己的私钥对摘要进行签名，生成数字签名
  3. 将原始消息、数字签名和自己的公钥一起发给 Bob

    公钥通常预先分发或通过证书获取，不需要每次发送

    若 Bob 已知 Alice 的公钥（如通过 CA 证书），则无需重复发送

  4. Bod 从 Alice 证书中提取她的公钥

    证书可以由 Alice 发送或向 PKI 申请

  5. Bob 使用 Alice 的公钥验证签名，

    若验证成功，得到一个哈希值 - 摘要1

    否则不是用户 Alice 发送的消息 - 主体鉴别

  6. Bob 再用同样的摘要算法对明文计算，得到摘要2，比较摘要1和摘要2

    如果相等，则能确定消息未被篡改 - 消息鉴别

    否则消息被篡改

  7. 事后，如果 Alice 反悔，不承认是自己发送的消息；Bob 可向颁发公钥的机构 PKI 申请认证
  8. PKI 或第三方仲裁机构可用 CA 的公钥验证签名，并确认用户 Alice 的身份 - 不可否认
Alice 向 Bob 发送消息并签名
加密与签名

Alice 使用 Bob 的公钥对消息进行加密 → 确保只有 Bob 能解密

Alice 使用自己的私钥对消息进行签名 → 确保消息来自 Alice，且未被篡改

解密与验证

Bob 使用自己的私钥解密消息

Bob 使用 Alice 的公钥验证签名，确认消息来源和完整性
