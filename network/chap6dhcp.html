动态主机配置协议

@DHCP
概述 Overview
动态主机配置协议 DHCP - Dynamic Host Configuration Protocol
由 DHCP 服务器控制一段IP地址范围，然后客户机登录服务器时就可以自动获得服务器分配的IP地址和子网掩码，从而顺利连通网络
使用客户/服务器 - C/S 方式，采用请求/应答方式工作
基于 UDP 工作

服务器运行在 67 号端口

客户运行在 68 号端口

系统组成 Components
DHCP Server：服务器
DHCP Client：客户
DHCP Relay Agent：代理
优点 Merits
客户机不需要手动配置 TCP/IP
减少配置网络上计算机的时间
提供安全可信的配置
有效利用 IP 地址

基本过程 Procedure

配置过程通过多个广播实现
1. Discover（发现）
DHCP 客户端启动后，广播 发送 DHCP Discover 报文
目的地址：255.255.255.255（本地广播）

受限广播地址 Limited Broadcast Address

路由器绝不会转发以 255.255.255.255 为目的地址的数据包

子网广播地址可以被路由器转发，但是通常被禁止

源地址：0.0.0.0（尚未拥有有效 IP 地址）
内容：包含客户端 MAC 地址（CHADDR 字段），用于标识自身
此时报文被同一广播域内所有 DHCP 服务器接收
CHADDR - Client Hardware Address；在标准以太网 DHCP 场景下，CHADDR 就是客户端的 MAC 地址
2. Offer（提供）
每个收到 Discover 报文的 DHCP 服务器根据客户端的 MAC 地址查找是否有为其保留的配置
若无，则从其 IP 地址池（Address Pool） 中选择一个可用 IP 地址，向客户端 广播 发送 DHCP Offer 报文
若有，再检测是静态绑定还是历史租约
-静态绑定，取出并发送
-历史租约，判断是否到期以及是否冲突，再根据情况处理
Offer 内容：包含提供的 IP 地址、子网掩码、租期、网关、DNS 等配置，以及 该 DHCP 服务器自身的 IP 地址
多个 DHCP 服务器可能同时响应，客户端通常只处理最先收到的 Offer
3. Request（请求）
客户端选择一个 Offer（通常是第一个），然后 广播 发送 DHCP Request 报文
告知所选的 DHCP 服务器：我接受你提供的 IP
通知其他 DHCP 服务器：我不使用你们的 Offer，请释放预分配的 IP
即使客户端已知道目标服务器 IP，仍使用广播；因客户端尚未完成配置，无法单播
4. Acknowledge（确认）
被选中的 DHCP 服务器收到 Request 后，若其中请求的 IP 与自己 Offer 的一致，则 广播 发送 DHCP ACK 报文
其他 DHCP 服务器收到 Request 后，发现不是自己的 Offer，便释放之前为该客户端预留的 IP 地址
ACK 内容：确认 IP 分配，并再次包含完整的网络配置参数
客户端收到 ACK 后，正式使用该 IP 地址及配置，完成初始化

在千兆局域网中，Windows/Linux 主机通常 300~800ms 内完成 DHCP

用户开机后，系统初始化、加载驱动、启动服务等过程本身就需要几秒到十几秒

DHCP 的几百毫秒几乎不可感知

DHCP 中继代理
DHCP 协议依赖于广播通信，尤其是在初始阶段（如 Discover 和 Request）
广播包（Broadcast）不能跨越路由器，因为路由器默认不会转发广播帧
如果客户端和服务器位于不同的子网（即不同广播域），那么客户端发出的广播请求无法到达服务器
每一个网络 至少有一个 DHCP 中继代理，它配置了 DHCP 服务器的 IP 地址信息
DHCP 中继代理以 单播 方式转发发现报文
DHCP 中继代理收到主机广播发送的发现报文后，就以单播方式向 DHCP 服务器 转发 此报文，并等待其回答
收到 DHCP 服务器回答的提供报文后，DHCP 中继代理再将其发回给主机

租用期 Lease Period

DHCP 服务器分配给 DHCP 客户的 IP 地址是 临时 的
DHCP 客户只能在一段有限的时间内使用这个分配到的 IP 地址 - 租用期
租用期的数值应由 DHCP 服务器自己决定
目的

防止 Ip 地址长期闲置

支持网络中设备动态加入/离开

实现地址池的自动回收与再分配

DHCP 定义了两个自动续租时间点T1/T2
DHCP 客户也可在自己发送的报文中（例如，发现报文）提出对租用期的要求
T1
租期的 50%

租期为 8 小时（28800 秒），则 T1 = 4 小时（14400 秒）

行为：客户端向原分配 IP 的 DHCP 服务器发送 DHCP Request 报文，请求续租
通信方式：单播；因为此时客户端已有有效 IP 和网关信息
目的：正常、安静地延长租期，无需重新经历完整 DHCP 流程
T2
租期的 87.5%

租期为 8 小时，则 T2 ≈ 7 小时（25200 秒）

触发条件：若在 T1 未能成功续租（如原服务器宕机）
行为：客户端广播 DHCP Request 报文，向任意可用的 DHCP 服务器请求续租
通信方式：广播；因无法确定原服务器是否可达
目的：作为备用机制，尽力保留当前 IP 地址
说明 Notation
若 T1 和 T2 均失败，到达 租期 100% 时，客户端必须停止使用该 IP 地址
随后重新发起完整的 DHCP Discover 流程获取新地址

Homework
  1. 翻译：

    DHCPDISCOVER – The client broadcast a DHCPDISCOVER packet in order to locate a DHCP server in the network, in some cases that the DHCP server isn’t in the same subnet of the client, you’ll need to configure in your network devices (usually routers) a DHCP Relay Agent, in order to transfer the DHCPDISCOVER packet to the DHCP server.

    DHCPOFFER – The DHCP server broadcast a DHCPOFFER packet to the client which includes an offer to use a unique IP address for the client.

    DHCPREQUEST – The client broadcast a DHCPREQUEST packet to the DHCP server with an answer, and “asks” from the server to “rent” the unique address that the server offer to her.

    DHCPACK – The DHCP server broadcast a DHCPACK packet to the client, in this packet the server acknowledge the request from the client to use the IP address, and provide to the client the IP address lease and other details such as DNS servers, default gateway, etc. if the server cannot provide the requested IP address or from some reasons the address is not valid the server sends DHCPNACK packet in stand of DHCPACK, more information about DHCPNACK is under the specific subject – DHCPNACK.

  2. 翻译：

    DHCP Relay Agent is any kind of host (usually a router or server) that listen to DHCP/BOOTP broadcast from clients on subnets without local DHCP servers.

    The DHCP Relay Agent forwards the packets from the clients and the DHCP server that sitting on different physical subnets to each other in order to supply ‘connection’ between the DHCP Server to the clients, and opposite (from the clients to the server).
