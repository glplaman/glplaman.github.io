@Key
加密和解密用的密钥 K 是一串秘密的字符串（即比特串）
解密算法是加密算法的逆运算
明文通过加密算法 E 和加密密钥 K 变成密文 Y
Y = EK(X)
或
C = EK(P)
接收端利用解密算法 D 运算和解密密钥 K 解出明文 X
X = DK(Y)
或
P = DK(C)
加密密钥和解密密钥可以一样，也可以不一样
密钥通常由密钥中心提供
密钥的传送必须使用安全通道
常见术语 Term
密钥 K - Key
明文 P - Plain
密文 C - Cipher
加密 E - Encode
解密 D - Decode

对称加密 Symmetric Encryption

加密密钥与解密密钥都使用相同密钥的密码体制
发送方和接收方必须事先共享同一个密钥
也称私钥体制；密钥始终保密
特点 Feature
密钥短
速度快
易于实现
适合加密 大量 数据
焦点 Focus
密钥分发困难（Key Distribution）：双方必须 安全 地共享同一个密钥，否则会被窃听
密钥管理复杂（Key Management）：每对通信双方都需要一个独立密钥，n 个用户需要约 n(n−1)/2 个密钥
多采用物理介质
加密类型 Type
流加密 Stream Ciphers

一次对一位或一个字节的数据进行加密

中性能优异、速度快

适合实时加密场景，如流媒体

分组加密 Block Ciphers

将数据按固定大小的块进行加密（例如128位的块）

速度通常慢于流密码，但应用极为广泛

DES - 已淘汰
Data Encryption Standard - 数据加密标准
DES 属于对称密钥密码体制，是一种分组密码
在加密前，先对整个明文进行分组；每一个组长为 64 位
然后对每一个 64 位二进制数据进行加密处理，产生一组 64 位密文数据
最后将各组密文串接起来，即得出整个的密文
使用的密钥为 64 位(实际密钥长度为 56 位，有 8 位用于奇偶校验)
仅取决于对密钥的保密，其算法是公开的
严重问题：DES 密钥长度较短
现在已经设计出搜索 DES 密钥的专用芯片
56 位 DES 已不再认为是安全的了
3DES - 已淘汰
Triple DES - 3重 DES
使用两个 56 位的密钥
把一个 64 位明文用一个密钥加密
再用另一个密钥解密
然后再使用第一个密钥加密
AES
Advanced Encryption Standard - 高级加密标准
是一种分组密码
分组长度为 128 位
有三种加密标准，其密钥分别为 128 位、192 位和 256 位
加密步骤复杂，运算速度比 3DES 快得多，安全性也大大加强
2002 年成为美国政府加密标准
现在是 ISO/IEC 18033-3 标准

非对称加密 Asymmetric Encryption

加密和解密使用不同的密钥
私钥 Private Key：带有个人特征，可用于 解密、验证签名
公钥 Public Key：用于 加密、签名
私钥自己保存，公钥公开；又称公开密钥密码体制，简称公钥体制
不存在密钥配送问题，容易导致中间人攻击
计算开销大，速度慢（比对称加密慢数百到上千倍）
不适合加密大量数据
通常由接收方生成公开密钥和私有密钥密钥对，并发送公钥给发送方
完整的通信过程，实际上需要2对密钥-4个密钥
特点 Feature
RSA
由三位开发者：Ron Rivest、Adi Shamir 和 Leonard Adleman 的姓氏的首字母组成
加密、数字签名
应用：X.509证书、SSL/TLS、PGP、SSH
ECC
Elliptic Curve Cryptography - 椭圆曲线密码学
加密、数字签名
应用：Bitcoin、TLS 1.3、移动设备、国密SM2
DSA
Digital Signature Algorithm - 数字签名算法
专门用于数字签名
应用：SSH
[] Bob 向 Alice 发送加密消息 - 公钥体制
不希望让第三方知道消息
Bob 使用 Alice 的公钥加密信息，发送给 Alice
Alice 用自己的私钥解密，获得信息

私有只有 Alice 自己有

但是 Alice 无法确认消息来自 Bob
也无法确认消息的完整性，如是否被人篡改过
[] GitHub 提供的 SSH 功能
基于 SSH（Secure Shell）协议
但它并不是用来远程登录服务器
而是利用 SSH 的安全认证和加密能力，来实现 Git 操作的身份验证和安全通信
中间人攻击
Man in the Middle Attack
中间人攻击指的是在通信双方的通道上，混入攻击者：

对接收方伪装成发送者

对放送放伪装成接收者

他监听到双方发送公钥时，偷偷将消息篡改，发送自己的公钥给双方。然后自己则保存下来双方的公钥
双方通信时，加密使用的都是攻击者的公钥；攻击者都可以拦截后解密，并且篡改信息内容再用对方公钥加密并发送
接收方拿到的是篡改后的信息
发送方和接收方都是在和中间人通信
应对措施：要防范中间人，我们需要使用公钥证书

    Alice wants to send a secret message to Bob

    Alice and Bob agree on a secret key

    Alice encrypts the plaintext message using the secret key

    Alice sends the encrypted ciphertext to Bob

    Bob decrypts the ciphertext back into plaintext using the same secret key

  2. 翻译：

    Symmetric encryption (or “private key” encryption) is the process of using a single key to both encrypt and decrypt data. It’s called “private key” because the use of a single encryption key necessitates that the key is always kept private.

  3. 翻译：

    Asymmetric cryptographic keys are usually used. Public and private keys are always generated as a pair and are mathematically linked to each other. In asymmetric encryption, data encrypted with the first key of a key pair can only be decrypted with the corresponding second key.

    A distinction is made between a public and a private key. The public key is freely accessible to everyone in the network. The private key, however, is only known to the owner and is not shared.s

  4. 翻译：
    A challenge with symmetric key encryption is safely exchanging the secret key between participants. Common solutions include:

    Meet in person to exchange keys

    Use asymmetric encryption to send the symmetric key

    Use a key exchange protocol like Diffie-Hellman

    Rely on a Public Key Infrastructure (PKI) and certificates
