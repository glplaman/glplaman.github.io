Tracert

概述 Overview
路由追踪，用于测试本端主机到某个目标主机所经过的路由，即：确定 IP 数据包访问目标所采取的路径
使用UDP协议发送数据
多用于内部检测网络故障节点情况
安全考虑，外网部分网络主机不允许被追踪，可能出现请求超时的情况
Ctrl+C强制退出测试状态
使用tracert /?查看完整命令
C:\Users\cnplaman>tracert /?

用法: tracert [-d] [-h maximum_hops] [-j host-list] [-w timeout]
               [-R] [-S srcaddr] [-4] [-6] target_name

选项:
    -d                 不将地址解析成主机名。
    -h maximum_hops    搜索目标的最大跃点数。
    -j host-list       与主机列表一起的松散源路由(仅适用于 IPv4)。
    -w timeout         等待每个回复的超时时间(以毫秒为单位)。
    -R                 跟踪往返行程路径(仅适用于 IPv6)。
    -S srcaddr         要使用的源地址(仅适用于 IPv6)。
    -4                 强制使用 IPv4。
    -6                 强制使用 IPv6。
-d：不解析主机名，只使用IP地址；命令的位置只能在host/IP前面；可以加快追踪时间
-h：指定最大跃点数追踪路由；查跟设备最近的几个连接点的问题，通常在网络问题中，先要排除前端跟设备直接连接的最近的几个设备是否有故障，如果这几个近点跟踪可以正常互通，那么问题可能就出现在后端
-w：当网络很慢，或者很卡时，要检测是哪个设备的反应速度比较慢，设个标准值|阈值，超过阈值的设备不显示
工作原理
源主机向目标主机发送一连串IP数据报来确定到目标所采取的路由
每个IP数据报的生存时间TTL依次加1
路径上每个路由器在转发数据包之前将TTL减1
TTL减为0时，路由器应该将"ICMP已超时"消息发回源主机
最后一个IP数据可以达到目标主机；因为采用的是无法交付的UDP，所有目标主机要向源主机发送"目标不可达"消息
通过检查中间路由器发回的“ICMP已超时”的消息确定路由
结果分析
tracert 默认对每一跳发送3个探测数据包（ICMP 或 UDP 包，取决于系统），目的是：

测试连接的延迟稳定性

检测是否出现丢包

提高结果的可靠性

结果分析
参数1 Hop Number

跃点编号

表示这是路径中的第几个路由器或网络节点

从你的电脑出发，每经过一次转发，跳数 +1
参数2 Round-trip Time, RTT

探测包到该节点并收到响应所用的时间

单位ms

第1个ICMP的往返时间
参数3 第2个ICMP的往返时间
参数4 第3个ICMP的往返时间
参数5 响应这一跳的设备的IP地址

如果有主机名，还会解析

[] 本机到baidu的路由情况 - 限定跳数
第一跳显然应该先到本机的默认网关
前3都是私有地址，表示还没有进入公网
第4条开始，没有收到回应

数据包到达了该跳设备，但该设备 不返回 ICMP “Time Exceeded” 消息

大多数公网上的核心路由器（尤其是运营商骨干网设备）为了安全和性能，默认关闭 ICMP 回显和 TTL 超时响应

你只允许追踪最多 5 跳，而实际路径可能更长。所以在第 5 跳中断，无法继续
