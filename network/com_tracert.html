Tracert

概述 Overview
路由追踪，用于测试本端主机到某个目标主机所经过的路由，即：确定 IP 数据包访问目标所选择的路径
tracert 默认对每一跳发送 3 个探测数据包（ICMP 或 UDP 包，取决于系统）

测试连接的延迟稳定性

检测是否出现丢包

提高结果的可靠性

安全考虑，外网部分网络主机不允许被追踪，可能出现请求超时的情况
使用 tracert /? 查看完整命令
tracert 
  [-d] 
  [-h maximum_hops] 
  [-j host-list] 
  [-w timeout]
  [-R] 
  [-S srcaddr] 
  [-4] 
  [-6] 
  target_name
-d
  • Do not resolve addresses to hostnames
  • 不解析主机名，只使用IP地址，可以加快追踪时间
  • 强烈建议 始终 加上 -d 参数
  • 如果目标没有配置对应的域名，或者运营商/路由器没有开启反向 DNS 记录，则无效
-h
  • Maximum hops
  • 指定追踪路由的最大跃点数
  • 使用分段隔离法排查

    通常先用较小的跃点值排除近端几个设备是否正常（最后一公里）

    如果近端设备正常，再增加跃点值排查远端（主干链路）

-w
  • 指定等待每个回复的超时时间（以ms为单位）默认 4000 毫秒
  • 参数控制的是 tracert 的“耐心程度”

    耐心越小（值越低），测试越快，但可能会漏掉响应稍慢的正常节点

    耐心越大（值越高），测试越准，但耗时也会成倍增加

  • 当网络很慢，或者很卡时，要检测是哪个设备的反应速度比较慢，设个标准值|阈值
  • 超过阈值的设备不显示
-j
  • Loose Source Route（松散源路由）
  • 强制指定数据包在到达最终目的地之前，必须经过 的中间节点（IP地址列表）
  • 精准定位特定路径的故障：当网络中存在多条路径时，你可以用 -j 强制数据包走某一条特定的骨干网链路。通过对比带 -j 和不带 -j 的结果，可以精确验证某一条特定路径的性能或延迟情况
  • 很多现代网络设备（路由器、防火墙）出于安全考虑，默认禁用了源路由功能。如果中间节点不支持，tracert 可能会直接报错（如“传输失败”），或者忽略你的 -j 设置。因此，更多用于 企业内部 网络或受控网络环境中的深度排查

命令的位置只能在host/IP前面

Ctrl + C 强制退出测试状态

工作原理
源主机向目标主机发送一连串 IP 数据报来确定到目标所采取的路由
每个 IP 数据报的生存时间 TTL 依次加 1
路径上每个路由器在转发数据包之前将 TTL 减1
TTL 减为 0 时，路由器应该将 "ICMP已超时" 消息发回源主机
最后一个 IP 数据可以达到目标主机；因为采用的是无法交付的 UDP，所有目标主机要向源主机发送"目标不可达"消息
通过检查中间路由器发回的 “ICMP已超时” 的消息确定路由

参数1
  • Hop Number
  • 跃点编号
  • 表示这是路径中的第几个路由器或网络节点
  • 从你的电脑出发，每经过一次转发，跳数 +1
参数2
  • Round-trip Time, RTT
  • 探测包到该节点并收到响应所用的时间
  • 单位ms
  • 第 1 个 ICMP 的往返时间
参数3
第 2 个 ICMP 的往返时间
参数4
第 3 个 ICMP 的往返时间
参数5
  • 响应这一跳的设备的 IP 地址
  • 如果有主机名，还会解析

中间星号 + 后面正常 = 节点禁 Ping，链路正常

全程星号 + 业务正常 = 目标端或路径禁 Ping，链路正常

全程星号 + 业务瘫痪 = 链路真的中断或严重拥塞，需要联系运营商排查

第一跳显然应该先到本机的默认网关
前3都是私有地址，表示还没有进入公网
第4条开始，没有收到回应

数据包到达了该跳设备，但该设备 不返回 ICMP “Time Exceeded” 消息

大多数公网上的核心路由器（尤其是运营商骨干网设备）为了安全和性能，默认关闭 ICMP 回显和 TTL 超时响应

你只允许追踪最多 5 跳，而实际路径可能更长。所以在第 5 跳中断，无法继续
