广播 vs 多播
广播 Broadcast 发送方将数据包发送到同一网络内所有主机，无论这些主机是否需要该数据
全1地址
多播 Multicast 发送方将数据包发送给一组特定的接收者，只有加入该组的主机才会接收数据
特定地址
IP 多播 IP Multicast

运行多播协议，如 PIM

多播 IP 地址
使用 D 类地址 - 标识位 1110xxxx xxxxxxxx xxxxxxxx xxxxxxxx
每一个 D 类地址标志一个多播组
地址范围：224.0.0.0 ~ 239.255.255.255

224.0.0.0 – 224.0.0.255：预留本地网段使用（如 224.0.0.1 表示所有主机，224.0.0.2 表示所有路由器），不会被路由器转发

224.0.1.0 – 238.255.255.255：可用于互联网或企业网络中的全局多播通信

239.0.0.0 – 239.255.255.255：私有多播地址（类似私有IP），仅在组织内部使用

224.0.0.1 是一个预定义的永久多播组，所有支持 IP 多播的主机默认都是该组的成员，无需显式加入

动态适应：必须动态地适应多播组成员的变化（这时网络拓扑并未发生变化），因为每一台主机可以随时加入或离开一个多播组

多播路由协议 PIM

Protocol Independent Multicast
专门用于 IP 多播的路由协议，是当前最主流的多播路由协议
不依赖特定的单播路由协议，而是利用现有单播路由表进行 RPF（Reverse Path Forwarding）检查
三个核心报文

成员报告 Membership Report

成员查询 Membership Query / 通用查询 General Query

成员离开组 Leave Group

特定组查询 Group-Specific Query

工作阶段 Phase
1. 加入多播组
当主机希望加入某个多播组时，会主动向该组的多播地址发送 IGMP 成员报告报文（Membership Report），声明自己为该组成员 - 主动报告
本地多播路由器收到该报告后

在自己的 IGMP 成员表（Membership Table）中添加一条记录：接口：Ethernet0/0；组地址：224.1.1.1；状态：有成员（Active）

将该组的成员关系通过多播路由协议 PIM 通告给互联网中的其他多播路由器，从而建立或维持多播转发路径

本地多播路由器开始转发多播流量
2. 探询组成员状态（成员保活机制）
本地多播路由器周期性地（默认每 125 秒）向本地网络广播 IGMP 成员查询报文（General Query） ，目的地址为 224.0.0.1（所有主机）
查询报文中包含一个 随机延迟值 N（0–10 秒），用于协调响应时机
响应抑制机制 Suppression：

同一组内的多个主机中，延迟最小者优先发送成员报告 Membership Report - 被动报告

其他成员在监听到已有报告后，取消自己的响应，避免冗余

只要有一个主机响应，多播路由器即认为该组在本地网络仍活跃，并继续转发该组的多播流量
若连续多次查询（通常为 3 次）均无任何响应，则判定该组在本地已无成员：

停止向该网络转发该组的多播数据

向上游多播路由器发送修剪 Prune 消息，通知其停止向本地下游发送该组流量，以节省带宽

3. 离开多播组
主机可通过以下任一方式离开多播组
主动离开：发送 IGMP 成员离开组报文（Leave Group），目的地址 224.0.0.2，即所有路由器

仅适用于 IGMPv2/v3

IGMPv1 不支持 Leave 报文：多播路由器只能靠周期性查询（每分钟一次）和超时来判断成员是否离开，效率较低

被动离开：不再响应后续的查询报文，多播路由器在多次查询无响应后自动判定其已离开
多播路由器收到后，不能立即停止转发（因为可能还有其他成员），于是发送 Group-Specific Query（针对该组的查询）
如果在若干次查询后无人响应 Report，多播路由器才真正停止向该子网转发该组的多播流
主机 H1 想要加入多播组 224.1.1.1；网络中有一台支持 IGMP 的多播路由器 R；使用 IGMPv2 协议
  1. 主机主动发送 IGMP Membership Report，目的 IP 地址：224.1.1.1（要加入的组地址），目的 MAC 地址：对应多播 MAC（01-00-5E-01-01-01）
  2. 步骤 2：多播路由器 R 接收并记录：该接口下有组播 224.1.1.1 的成员
  3. 开始向该接口转发发往该组播的流量（前提是上游已有多播源树建立）
主机 H1 离开多播组 224.1.1.1；网络中有一台支持 IGMP 的多播路由器 R；使用 IGMPv2 协议
  1. 主机向本地网段发送 IGMP Leave Group 报文，目的 IP：224.0.0.2，所有多播路由器；报文中携带要离开的组地址：224.1.1.1
  2. 多播路由器收到 Leave 后，发送特定组查询（Group-Specific Query），目的 IP：224.1.1.1，确认该组是否还有成员
  3. 如果还有其他主机属于该组，回应 IGMP Report
  4. 多播路由器一旦收到 Report，就确认仍有成员，继续转发多播流
  5. 若无响应，多播路由器停止向该接口转发 224.1.1.1 的流量
  6. 多播路由器向上游发送 Prune 消息，剪枝多播分发树
