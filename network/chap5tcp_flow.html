流量控制

@Flow Control
Flow control
接收方控制发送方不要发太快，以便接收方能来得及处理
接收方维护一个 接收窗口 rwnd ，在每个 ACK 报文中，告知发送方自己的接收窗口 rwnd 大小
发送方根据该值动态调整自己的发送窗口大小，确保不会发送超过接收方处理能力的数据
发送方可以多次发送；直到把发送窗口已满
接收方采用累计确认
0窗口 Zero Window
当接收方缓冲区满时，会通告窗口大小为 0

ACK = 1; rwnd = 0

发送方停止发送数据
之后接收方有空间了，应及时让发送方知道可以继续发送数据
为了避免接收方的非0窗口通知丢失，导致发送方等待 - 死锁
TCP 为每个连接都创建了一个持续计时器 persistence timer
只要发送方收到0窗口，就启动计时器
计时到，发送方主动发送一个1 byte 的窗口探测报文 Window Probe，以便确定是否可以恢复正常数据通信
接收方收到后必须回复 ACK，并携带当前真实窗口大小

ACK = 1; rwnd = 200

发送方收到后，恢复传输
若收到窗口仍为 0，则发送方重启计时器，继续等待

ACK = 1; rwnd = 0

基本过程 Procedure
A 向 B 发送数据，MSS = 100 bytes
在连接建立时，B 告诉 A：我的接收窗口 rwnd = 400 bytes
右侧为A的发送方窗口
