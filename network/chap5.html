运输层

@Transport Layer
概述 Overview
定位：OSI七层模型中的第4层：网络层之上、应用层之下
任务：为应用进程提供端到端的逻辑通信服务

端：应用进程，逻辑层面

运输层以下各层的任务：解决网络到网络、主机到主机的通信
运输层将主机间通信提升为进程间通信；向上层屏蔽底层网络细节（如拓扑、路由、链路类型）
采用逻辑 端口 来标识不同的应用进程，实现进程间的准确通信

计算机通信实际上应用进程之间的通信

运输层是应用进程通信的桥梁

通过端口实现精准寻址，利用 TCP/UDP 提供灵活的服务选项

它不仅完成端到端的数据传输，还承担可靠性保障、资源协调与网络保护等关键任务，是网络体系结构中承上启下的核心层次

服务类型 Type
  1. 用户数据报协议 UDP，User Datagram Protocol
  2. 传输控制协议 TCP，Transmission Control Protocol
服务类型 Type
UDP TCP
连接方式 无连接（无需握手） 面向连接（建立连接、通信、释放连接）
可靠性 不可靠（无确认、无重传） 可靠（序号、确认、超时重传、连接管理、流量管理、拥塞管理）
开销 小（首部仅8字节） 大（首部20+字节，含控制字段）
适用场景 实时音视频、广播、DNS 网页浏览、文件传输、邮件等
职责 Responsibility
运输层作为网络体系结构中的关键层，为上层应用屏蔽了底层网络的复杂性，提供了灵活可靠的数据传输服务
  1. 复用与分用

    复用 Multiplexing：发送端多个应用进程的数据通过运输层封装，共享同一网络连接

    分用 Demultiplexing：接收端根据目的端口号将数据准确交付给对应应用进程

  2. 差错检测

    通过校验和检测传输错误

    TCP还提供差错纠正机制
