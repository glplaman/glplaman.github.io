差错检测 Error detection
检测数据在传输或存储过程中是否发生了错误
数据传输没有百分百的准确，总是有误差存在
常见错误 Exceptions
  • 比特差错

    • 你发送的是1，我收到的是0

    解决：循环冗余检测 CRC

  • 帧丢失 Frame Loss

    • 指一个或多个数据帧在传输过程中未能到达接收方

    解决：序号 + 确认机制 (ACK) + 超时重传

  • 帧重复 Frame Duplication

    • 同一个数据帧被多次接收，即接收方收到了两个或更多相同的帧

    解决：序号 + 确认机制 (ACK) + 超时重传

  • 帧失序 Frame Out-of-Order

    • 数据帧没有按照发送顺序到达接收方

    解决：序号 + 确认机制 (ACK) + 超时重传

循环冗余检测 CRC

概述 Overview
循环冗余检测 CRC - Cyclic Redundance Check
在数据 M 的后面附加上供检测用的 n 位冗余码再发送出去
冗余码，又称帧校验序列 FCS – Frame Check Sequence
实现 Implementation
在 M 的数据后面加上 n 个 0，即消息 左移 r 位
用生成多项式 P 按照模 2 运算去除 M+n
得到的余数 R 就是冗余码 - 如果位数不够 n 位，前面要补 0
发送的报文就是 数据 M + 冗余码 R
接收端用相同的生成多项式对收到的完整报文（消息+冗余码）再次进行模2除法；若余数为0，则认为数据正确；无传输错误
通常情况下，生成多项式 P 的二进制位数比它生成的冗余码（校验码）的位数多 1 位
冗余码（校验码）的位数 r 是由生成多项式 P(x) 的最高次数决定的

若消息 M = 101001，P = 1101，使用 3 位冗余码，取 n = 3；求冗余码和最后的报文。
答：

p 对应的生成多项式 p(x) = x3 + x2 + 1

则除数为 P，被除数为 M + 000 = 101001000

模2运算后，余数 R 为 1，补足3位 → 001

故发送 M + R = 101001001

若消息 M = 11010，P(x) = x3 + x2 + 1，求：
  1. 冗余码
  2. 发送的报文
  3. 若收到的报文为11110000，传输有没有差错？
答：

生成多项式的最高次幂是3 → n = 3

生成多项式对应的二进制 P = 1101

被除数 M + n = 11010000

除数 P = 1101

∴ 冗余码 R = 0 → 000

发送报文为 M+R = 11010000

用 11110000除以 1101，余数为101，不为0，接收端判定数据错误

其它校验机制 Other

奇偶校验
仅通过增加1位校验位，使数据中“1”的个数为奇数（奇校验）或偶数（偶校验）
只能检测单个比特错误，无法检测偶数个比特错误
也无法定位错误位置
二维奇偶校验
在奇偶校验基础上扩展为行列双重校验
可检测并纠正单比特错误，对突发错误也有一定检测能力
但实现复杂度高于普通奇偶校验
校验和
将数据按字节或字相加后取反作为校验值
常用于IP、TCP等协议头校验
能检测大部分错误，但对某些特定错误模式（如数据位交换）可能失效
检错机制比较
item desc
奇偶校验 最简单，只能检错（且只能检奇数个错），不能纠错
二维奇偶校验 稍微强一点，能检错也能纠正单比特错误
校验和 互联网常用（IP/TCP），软件实现快，但检错能力不如CRC
CRC 硬件实现快，检错能力最强（漏检率极低），局域网最常用
