公钥基础设施

@PKI
Public Key Infrastructure
用于创建、管理、分发、使用、存储和撤销数字证书及公钥的综合体系
其核心目标是建立一个 可信 的身份认证与安全通信环境
主要功能 Function
身份认证：通过数字证书将用户的公钥与其真实身份（如姓名、域名、组织）绑定
信任传递：利用证书链（根 CA → 中间 CA → 用户证书）实现跨域信任
数据完整性与不可否认性：支持数字签名，确保消息来源真实、未被篡改
密钥管理：安全地生成、存储、更新和吊销密钥对
访问控制与审计：为系统提供基于证书的身份识别机制
核心组件 Component
CA（Certificate Authority）：权威机构，负责签发和吊销数字证书
RA（Registration Authority）：负责审核用户身份信息，提交给 CA
数字证书：X.509 格式文件，包含用户公钥、身份信息、有效期和 CA 签名
证书库（Repository）：存放已签发证书和 CRL（证书吊销列表）
CRL / OCSP：用于实时查询证书是否有效
终端实体：使用证书的用户、服务器或设备（如网站、移动应用）
工作流程简述 Workflow
  1. 用户生成密钥对（私钥保密，公钥提交）
  2. 向 CA 提交 CSR（证书签名请求）
  3. CA 验证身份后，用其私钥签发证书
  4. 用户部署证书，用于加密通信或数字签名
  5. 接收方使用 CA 的公钥验证证书有效性，进而信任该公钥
应用场景 Application
HTTPS/SSL/TLS：网站身份认证与安全传输
电子合同与电子签名：具备法律效力的数字签署
电子政务与身份认证：公民在线办事、数字身份证
金融交易：银行系统、支付平台的安全接入
代码签名：软件发布时证明来源可信
物联网设备认证：设备入网前身份验证
[] Github SSH登陆
  1. 客户端发起连接

    SSH 客户端连接到服务器的 22 端口

    双方协商加密算法、协议版本等

  2. 服务器要求身份认证

    服务器看到你想用 user 账号登录

    它检查 ~user/.ssh/authorized_keys 文件，发现里面有你的 公钥

  3. 服务器发送“挑战”（Challenge）

    服务器生成一个随机字符串（比如一串 256 位的随机数），并发送给客户端

    这个挑战是一次性、不可预测的，防止重放攻击

  4. 客户端用私钥签名

    你的 SSH 客户端（如 OpenSSH）自动找到对应的 私钥（如 ~/.ssh/id_ed25519）

    用该私钥对这个随机挑战进行 数字签名（不是加密！）

    把签名结果发回服务器

  5. 服务器用公钥验证

    服务器用 authorized_keys 中存储的 你的公钥 去验证这个签名

    如果签名有效 → 证明你确实持有对应的私钥 → 身份合法 → 允许登录

    如果无效 → 拒绝登录
