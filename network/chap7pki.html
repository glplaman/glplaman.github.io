公钥基础设施

@PKI
Public Key Infrastructure
用于创建、管理、分发、使用、存储和撤销数字证书及公钥的综合体系
其核心目标是建立一个 可信 的身份认证与安全通信环境
主要功能 Function
身份认证：通过数字证书将用户的公钥与其真实身份（如姓名、域名、组织）绑定
信任传递：利用证书链（根 CA → 中间 CA → 用户证书）实现跨域信任
数据完整性与不可否认性：支持数字签名，确保消息来源真实、未被篡改
密钥管理：安全地生成、存储、更新和吊销密钥对
访问控制与审计：为系统提供基于证书的身份识别机制
核心组件 Components
注册机构 RA - Registration Authority）：负责审核用户身份信息，提交给 CA
颁发机构 CA - Certificate Authority）：负责签发和吊销数字证书

证书吊销列表 CRL - Certificate Revocation List

CRL / OCSP：用于实时查询证书是否有效
终端实体：使用证书的用户、服务器或设备（如网站、移动应用）
工作流程简述 Workflow
  1. 用户生成密钥对和证书签名请求 CSR - Certificate Signing Request
  2. 用户向 RA 提交公钥和 CSR
  3. RA 验证用户身份（如：身份证、企业资质等）；如果验证通过，将申请转发给 CA
  4. CA 使用其私钥对发送方的公钥和身份信息进行数字签名，生成数字证书，并返还给用户
  5. 用户部署证书，用于加密通信或数字签名
  6. 接收方使用 CA 的公钥自己或向第三方验证
应用场景 Application
HTTPS/SSL/TLS：网站身份认证与安全传输
电子合同与电子签名：具备法律效力的数字签署
电子政务与身份认证：公民在线办事、数字身份证
金融交易：银行系统、支付平台的安全接入
代码签名：软件发布时证明来源可信
物联网设备认证：设备入网前身份验证
Github SSH 请求并验证仓库的读写权限
  1. SSH 客户端发起连接到服务器的 22 端口
  2. 双方协商加密算法、协议版本等
  3. 服务器要求身份认证；会查找所有绑定到你账户的公钥
  4. 服务器发送挑战 Challenge 给 SSH 客户端；要求 SSH 客户端用对应的私钥对该挑战进行签名

    这个挑战是随机、一次性、不可预测的，防止重放攻击

  5. SSH 客户端找到对应的 私钥（如 ~/.ssh/id_ed25519），用私钥签名，把签名结果发回服务器
  6. 服务器用存储的你的公钥去验证这个签名

    如果签名有效 → 证明你确实持有对应的私钥 → 身份合法 → 允许访问

    如果无效 → 拒绝访问
