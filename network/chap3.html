封帧 Frame Packaging

帧 Frame 是数据链路层传输的基本单位
为了正确识别一帧数据的开始和结束，需要使用特殊的界定符来标记边界
要发送的数据分别加上首部和尾部再发出去
封帧后的数据长度不应超过 MTU - Maximum Transfer Unit；最大传输单元
帧界定符 Frame Delimiters
SOH - Start Of Header；编码：01
EOH - End Of Header；编码：04
EOH Data SOH

差错检测 Error detection

凡是接收到的帧，都被认为是正确的帧 - 因为错误的帧已经被丢弃了
检测数据在传输或存储过程中是否发生了错误
数据传输没有百分百的准确，总是有误差存在
常见错误是比特差错；你发送的是1，我收到的是0
衡量 Measurement
误码率 BER - Bit Error Rate
某段时间内，传输错误的比特占传输比特总数的比率
措施 Solution
在数据M的后面附加上供检测用的n位冗余码再发送出去
冗余码，又称帧校验序列 FCS – Frame Check Sequence
实现 Implementation
循环冗余检测 CRC - Cyclic Redundance Check
在M的数据后面加上n个0
用生成多项式P按照模2运算去除M+n
得到的余数R就是冗余码 - 如果位数不够n位，前面要补0
通常情况下，生成多项式P的二进制位数比它生成的冗余码（校验码）的位数多1位
冗余码（校验码）的位数 r 是由生成多项式 P(x) 的最高次数决定的
模2/异或

p对应的生成多项式 p(x) = x3 + x2 + 1

则除数为P，被除数为M+000=101001000

模2运算后，余数R为1 → 001

故发送M+R=101001001

[] 若消息 M=11010，P(x)=x3 + x2 + 1，求冗余码和最后的报文。

生成多项式的最高次幂是3 → r=3

生成多项式对应的二进制 P = 1101

被除数 M+r = 11010000

除数 P = 1101

结果 r = 0 → 000

实际发送报文为 11010000

其它错误 Other

帧丢失 Frame Loss
指一个或多个数据帧在传输过程中未能到达接收方
解决 - 超时重传
帧重复 Frame Duplication
同一个数据帧被多次接收，即接收方收到了两个或更多相同的帧
解决 - 序号
帧失序 Frame Out-of-Order
数据帧没有按照发送顺序到达接收方
解决 - 序号
