文件传输协议

@FTP
概述 Overview
文件传输协议FTP - File Transfer Protocol：既是一个协议，又是一个应用
采用TCP协议；协议端口：20/21
提供交互式的访问，允许客户指明文件的类型与格式，并允许文件具有存取权限
屏蔽了各计算机系统的细节，因而适合于在异构网络中任意计算机之间传送文件
是文件共享协议的一个大类
FTP中的两个概念

下载 Download：从远程主机拷贝文件至自己的计算机上

上传 Upload：将文件从自己的计算机中拷贝至远程主机上

使用客户/服务器 C/S 模式

一个 FTP 服务器进程可同时为多个客户进程提供服务

连接类型 Types of Connection
控制连接 Control Connection

发送控制信息，例如用户身份验证（用户名和密码）、更改远程目录的命令、检索和存储文件的命令等

使用端口 21

数据连接 Data Connection

传输实际的文件内容

使用端口 20

使用过程 Procedure
连接FTP服务器 - Connect to the FTP Server
定位到文件目录 - Navigate Directories
传输文件 - Transfer Files
管理文件 - Manage Files
关闭连接 - Close the Connection

工作模式 Mode

主动模式 Active Mode
FTP 的原始设计
工作过程：

客户端通过 随机端口（如 54321） 向服务器 21 端口 发起控制连接

客户端发送 PORT 命令，告知服务器：“请连接到我的 65432 端口”

服务器从 20 端口 主动连接到客户端的 65432 端口，建立数据连接

文件开始传输

特点

数据连接由 服务器发起

服务器使用固定端口 20

客户端需允许服务器的入站连接

不适合防火墙/NAT 后的客户端（因服务器无法穿透防火墙）

被动模式 Passive Mode
工作过程：

客户端通过 随机端口（如 54321） 向服务器 21 端口 发起控制连接

客户端发送 PASV 命令，请求服务器进入被动模式

服务器响应：返回一个 临时高编号端口（如 51230），并说：“我已打开该端口，请连过来”

客户端从自己的 65432 端口 主动连接到服务器的 51230 端口，建立数据连接

文件开始传输

特点

数据连接由 客户端发起

服务器使用 随机高编号端口（>1023）

客户端只需出站连接，无需入站权限

适合防火墙/NAT 后的客户端

实操 Drill

下载 Download
点击 FileZilla 分别下载服务器端和客户端端
安装 Install
服务器端安装时，根据需要设置管理密码
安装完毕后，桌面会出现3个图标，分别是管理FTP，开启FTP服务和关闭FTP服务；后面两个非必须
配置FTP服务器 Config
指定IP地址、端口号和使用方式
配置用户 User
组：将特定用户划分到不同的组里，用以区分不同的权限和访问目录
用户：FTP使用者的账号，并不指特指某个计算机用户；可以多人使用同一个用户；比如互联网1B都可以使用xit这个用户
不同的组/用户通常指定不同的访问目录
用户可以单独使用，不一定非要划分到某个组
使用FTP服务
打开资源管理器[win+E]，在地址栏输入设置的FTP服务器地址，回车并输入密码，即可访问FTP资源
常见问题 Q&A
浏览器不支持：所有采用了最新的谷歌内核的浏览器，都不支持FTP模式了
推荐使用资源管理器WIN+E打开或使用专门的客户端
Microsoft Edge currently only supports anonymous FTP login via the Internet. For FTP login over LAN, logging in using either the anonymous account or username/password is not supported.
A possible to solution would be to use either of those other browsers or use an actual FTP client like FileZilla or similar.

Homework
  1. 为什么FTP要区分不同的工作模式？
  2. FTP 的控制连接始终使用服务器的 21 端口。（）
  3. 在主动模式下，数据连接由客户端发起。（）
  4. 被动模式中，服务器使用 20 端口进行数据传输。（）
  5. FTP 的 20 端口仅在主动模式（Active Mode）下使用，而在被动模式（Passive Mode）中通常不会使用 20 端口。（）
  6. FTP 主动模式更适合客户端位于防火墙或 NAT 后的网络环境。（）
  7. FTP 的控制连接和数据连接使用同一个 TCP 连接。（）
  8. 主动模式下，客户端需提前告知服务器自己的 IP 地址和用于接收数据的端口号。（）
  9. 现代 FTP 客户端（如 FileZilla）默认使用主动模式。（）
  10. 在被动模式下，所有连接（包括数据连接）均由客户端主动发起。（）
  11. 如果 FTP 服务器只开放了 21 端口，被动模式仍可正常传输文件。（）
