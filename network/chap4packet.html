标识 Identification、标记 Flags、片偏移部分 Fragment Offset
这3个字段用于IP数据报分片
Identification：16bit；同一个数据报的不同分片应具有相同的标识；每产生一个数据报[不是数据分片]就加1，充当计算器的功能
Flags：3bit，包括：MF + DF + 保留位0

MF：More Fragment；1：还有分片；0：没有分片

DF：Don’t Fragment；1：不允许分片；0：允许分片

Fragment Offset：13bit，以 8字节 为单位，指出分片数据报的数据部分在 原 数据报中的偏移部分；必须为整数

8bit，以秒s为单位

首部校验和 Header Checksum
16bit
只校验首部：用来校验数据传输过程中，首部是否出现差错
每经过一个路由器，都要重新计算
为加快转发速度，IPv6中不再计算
计算过程

初始化：将首部校验和字段设置为0!!!

头部分割：将IP首部每16bit分为一组；20个字节的首部最终被分成10组；每组2个字节/16bit

累计求和：所有分组累计求和，即每次用前面的累积和去加后面的分组；如果求和结果产生进位，则将进位加到最低位，如 0x10001 → 0x0002

结果取反：对最终结果求反码，即得到校验和

字段回填：将计算结果填入首部校验和字段

接收端验证过程

将收到的IP数据报首部同样按16位分组

对所有分组（包括校验和字段）进行二进制反码求和

如果结果全为1（即0xFFFF），则校验通过，数据未出错

如果结果不全为1，则数据在传输过程中出现错误；被丢弃

案例 Cases

[] 已经某IP报首部字段THL为0101，总长度字段TL为0000 0011 1111 1100，求数据部分字段DATA的长度
首部长度为(0101)2*4 = 5*4 = 20 字节
总长度为(0000 0011 1111 1100)2 = 1020 字节
故：数据部分长度为：总长度-首部长度 = 1020 - 20 = 1000 字节
[] 已知采用固定长度首部的数据报，数据部分位3800字节，如何分片？（分片不超过1420字节）。
数据报长度 = 首部 + 数据 = 20 + 3800 = 3820字节
分片后不能超过1420字节，所以每片的数据部分为最大为1400字节
假设标识ID为12345
IP数据报的分片

分片1 20+1400 12345 1 0 0/8
分片2 20+1400 12345 1 0 1400/8
分片3 20+1000 12345 0 0 2800/8
[] 采用固定首部的某IP数据报长度为1500B，目标网络的MTU是800B，求分片数量和偏移。
原始数据报
Header Data

偏移量不是整数；分片方案失败
原始方案
TL FRAG OFFSET

分片2 20B + 700B 780/8=97.5
调整分片长度，不超过800且能被8整除即可；所以分片方案不唯一
取8的整倍数，即：[780/8]*8=776B

TL FRAG OFFSET

分片2 20B + 704B 776/8=97
根据分片的数据长度去找8的整倍数字节
