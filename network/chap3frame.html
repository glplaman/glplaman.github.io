1. 前导码 Preamble
7 Bytes
0xAA AA AA AA AA AA AA
用来 同步和定位 帧开始
用于物理层接收端的时钟同步。接收机通过检测这个规律的信号，调整自己的采样时钟，使其与发送方同步
是帧接收的第一步，不包含在实际数据长度内
2. 帧起始定界符 SFD，Start Frame Delimiter
1 Byte
0xAB；10101011
标志着有效帧的开始。打破了 Preamble 的交替模式（最后两位为11），告诉接收端：现在开始接收真正的帧头了
SFD 是帧的正式起点，但不是 MAC 帧的一部分
3. 帧间隔 IFG，Inter-Frame Gap
12 Bytes
帧和帧之间的间隔
紧跟在当前帧的 FCS 之后，下一个帧的 Preamble 之前
它不属于帧本身，但却是连续发包时的必要间隔
体现在物理介质上（即线路上传输完一个帧后，空闲 12 Bytes 时间再传下一个）
因为帧之间有传输间隙，所以不需要帧结束的界定

接收方一旦检测到线路空闲超过 12 Bytes / 96 bits 时间，就认为当前帧结束，不需要像 PPP 那样专门在尾部加一个 0x7E 字节

以太网靠"开头同步（Preamble + SFD）+ 尾部空闲（IFG）"来界定帧，而不靠尾部标志 Flag

帧校验序列，FCS，Frame Check Sequence
4 Bytes
用于检错
校验范围：目的 MAC + 源 MAC 地址 + 数据 Data + 类型和长度 + FCS；不包括前导码和帧起始定界符
使用 CRC-32 算法计算出的校验码
接收端收到帧后，重新计算CRC并与FCS比较，若不一致则认为帧损坏，丢弃该帧
位于帧的末尾
接收方（网卡/NIC）收到帧后，会：

使用相同的 CRC-32 算法 对帧内容（目的 MAC 到数据）重新计算 CRC

将计算结果与帧中的 FCS 字段比对

若不匹配 → 帧被判定为损坏 → 立即丢弃，不通知上层

TYPE: 0x0800，标明上层协议是 IPv4，载荷 DATA 为 IP 数据包/封装数据包
ARP请求的帧结构
DEST ADDR (目的MAC地址): FFFF.FFFF.FFFF，以太网的广播地址。当一台设备不知道另一台设备的 MAC 地址时，它就会发送广播，询问网络上的所有设备。ARP 请求最显著的特征
SRC ADDR: 0060.7086.CC04，这是发起 ARP 请求的那台设备的物理地址
TYPE: 0x0806，这表明以太网帧的“数据（DATA）”部分里面封装的是一个 ARP 报文
