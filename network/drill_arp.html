地址解析协议

ARP

实验内容
地址解析协议 ARP
实验目的
掌握地址解析协议的基本原理和过程
实验步骤
阶段1 准备
  1. 搭建拓扑

    3台 PC

    1台 2960 交换机

  2. 配置各主机IP，采用默认掩码255.255.255.0

    PC0：192.168.1.1

    PC1：192.168.1.2

    PC2：192.168.1.3

  3. 使用监视工具 打开 PC0、PC1、PC2 的 ARP 表
  4. 使用监视工具 打开 Switch0 的 MAC 表
阶段2 Ping
  1. PC0 → 桌面 Desktop → 命令行 Command Prompt，使用 Ping 命令

    测试到 PC1的连通性，观察 PC0、PC1的ARP 表、Switch0 的 MAC 表

    测试到 PC2的连通性，观察 PC0、PC2的ARP 表、Switch0 的 MAC 表

  2. 持续单击快进 ，再次观察几个表的变化
  3. 依次清除PC0、PC1、PC2的 ARP 缓存，查看各表变化；为什么交换机的 MAC 会增加相应的条目
    4. arp -d
  4. 持续单击快进 至交换机的 MAC 表为空
阶段3 模拟简单报文
  1. 切换到模拟模式 Simulation
  2. 编辑过滤器 Edit Filter，ARP 和 ICMP
  3. PC0 向 PC1 发送数据：单击"添加简单 PDU " → 再单击"PC0"作为发送方 → 再单击"PC1"作为接收方
  4. 单步执行 ，查看 PDU 的发送过程

    PC0 先缓存数据，发起 ARP request（广播）请求 PC1 的 MAC 地址

    交换机广播分组

    PC1 接收分组并回复

    PC2 丢弃分组

    PC0 封装并通信

    ...

  5. 删除 Delete 场景或新增 New 一个场景
  6. PC0 再次向 PC1 发送数据；交换机不需要广播，直接转发给 PC1；PC1回复

进阶 ARP

跨网 ARP
主机 → 交换机 → 路由器 → 交换机 → 主机
如果目标主机和源主机不在同一网段，目标主机就向网关发 ARP 请求，然后封装报文、发给网关
如果网关没有目标主机的 ARP 条目，网关发起 ARP 请求
如果网关有目标主机的 ARP 条目，网关直接把报文发给目标主机
